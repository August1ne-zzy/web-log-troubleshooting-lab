# 中文讲解：先看成品，再逐部分理解

这个项目的主题是：**用程序记录服务行为，再用数据确认哪里出了问题。** 它现在是本地实验，不是对真实网站的生产运维。

助手先完成了实现、测试与示例整理；这些交付不等于你已经独立理解或完成了全部实现。以下是之后一起讲解的路线，不是让你一次做完的作业。

## 1. 服务：`server.py`

服务是一段保持运行、等待请求的程序。收到 GET 请求后，根据路径执行不同分支，返回状态码与 JSON 正文。例如 `/slow` 的 `time.sleep(0.5)` 主动制造半秒等待。

状态码表达处理结果，耗时表达速度。返回 500 时服务仍然可以在运行。停止服务后的连接拒绝发生在收到 HTTP 响应之前，不会出现在这个服务的访问日志里。

`/report` 额外读取一份配置，模拟“某项功能依赖的资源是否准备好”。这里只用布尔开关，没有真实外部依赖。

## 2. 生成请求：`generate_requests.py`

它扮演客户端，重复请求 `/`、`/missing`、`/error`、`/slow`。浏览器也能扮演客户端，但可能额外访问 favicon，影响固定请求数；脚本方便重复相同实验。

两轮固定请求共 8 次，路径和状态数量可以事先计算。这样我们有一个能独立核对的答案，能够发现后续统计有没有算错。

## 3. 日志：`access.jsonl`

这是程序运行留下的记录，每行是一个 JSON。主要看路径、状态码、耗时，再用 request_id 把页面与日志中的同一次请求对应起来。

日志是运行结果，源代码是执行规则；所以日志里看不到源代码中的 `elif`。UTF-8 是文本编码，JSONL 是组织文本记录的格式，两者不同。

## 4. 读取与清洗：`import_logs.py`

文件里有文字，不代表每行都是能用的数据。例如耗时是负数、状态码是字符串、时刻没有时区，都会影响分析。程序先验证并统一表示，再决定是否存储；坏行会报告位置和原因。

时间统一为 UTC 是为了可比较。例如日本时间 19:00 和 UTC 10:00 可以表示同一时刻，不能因为写法不同就当成冲突。没有时区的时间不猜测。

“清洗”不表示随意修改数值；这里主要是字段校验、时间与 UUID 表示统一、按固定规则处理重复和异常。

## 5. 存储：SQLite 和 `sql/schema.sql`

SQLite 把记录保存到本地一个数据库文件，不需要另外启动数据库服务器。`requests` 是表，每一行保存一次请求，列保存字段。

`request_id` 是主键，用来保证同一次请求只保存一行：

- 第一次读 8 条日志：保存 8 行。
- 再读同一文件：认出相同 ID 和内容，新增 0 行。
- 再发送一次请求：产生新 ID，应该新增一行。
- 同一 ID 却变了状态码：报告数据冲突，不覆盖旧证据。

这些规则保护统计正确性，不代表对服务的请求进行了去重。

## 6. 分析：`sql/summary.sql`、`sql/by_path.sql`、`analyze.py`

SQL 向数据提问，例如：

```sql
SELECT path, COUNT(*) AS request_count
FROM requests
GROUP BY path;
```

含义是：按路径分组，数每组有多少行。`COUNT(*)` 不是请求生成器发出的次数，而是数据库中符合当前查询范围的记录数，所以导入和去重必须先正确。

`analyze.py` 负责运行 SQL，并把结果输出成 JSON 或 Markdown。当前没有复杂前端。所有比例都注明分母；详细口径见日文 `docs/metrics.md`。

## 7. 自动实验：`demo.py`、`incident_demo.py`

`demo.py` 把前面的步骤接起来运行：服务 → 请求 → 日志 → 两次导入 → SQL → 报告。输出文件保存为证据。

`incident_demo.py` 额外演示正常配置、错误配置、修正配置三个阶段。三个阶段发送相同的两个路径，分别分析，避免把所有阶段混在一起后误读“恢复后仍有历史错误”。它知道预设原因，属于受控复现；并不证明你已经能独立诊断未知故障。

## 8. 验证：`tests/test_pipeline.py`

测试的目标是保护结论：重复导入不能让错误率变化，坏数据不能混入分母，500 ms 边界要明确，修正配置后受影响路径要恢复。测试通过说明检查过的条件成立，不代表所有情况下都没问题。

## 下一次一起讲解的顺序

先看 `examples/pipeline/report.md` 的一张结果表，再回到 8 条日志手算一次数量和错误率，接着追踪对应 SQL。每次只讲一条链路，确认你能说出输入、处理、输出，再进入下一部分。

求职展示的价值来自“别人能复现、结果有验证、你能解释”，不是文件数量或使用技术的数量。完整首版还需要本人理解、手动排查练习与有用途的图表；现在不生成已熟练掌握的简历声明。
